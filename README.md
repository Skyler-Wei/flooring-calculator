

## v6.0 使用方式

直接在浏览器打开 `index.html`。保留原版左右分栏、结果卡片和两个 3D 视图。Tailwind CSS 和 Three.js 沿用原有 CDN，需要网络；3D 加载失败时数值计算仍可使用。

右上角地球图标旁的语言选择支持英文、中文和越南语。切换时同步更新页面标题、字段、选项、计算结果和错误提示，保留输入及计算方案；浏览器允许本地存储时会记住选择。数字显示使用对应语言的格式，单位及柜型代码保持通用写法。

### 已确认的计算规则

首次打开时按浏览器提供的系统语言偏好选择英文、中文或越南语（支持 en-US、zh-CN、zh-TW、vi-VN 等地区代码），没有匹配语言时使用英文。用户手动选择过语言后优先使用已保存的选择；自动检测不会保存为手动偏好。

- 单片重量只计算地板本体：长 × 宽 × 本体厚度 × 本体密度 ÷ 1,000,000，单位 kg。底垫计厚度、不计重量。
- 纸箱长宽默认分别为地板长宽 + 4 mm，可分别手动覆盖，重置后恢复联动。箱高 =（本体厚度 + 底垫厚度）× 每盒片数 + 高度余量，高度余量默认 4 mm，独立于长宽。
- 每盒片数固定为用户输入的正整数；每托采用同一层内布局、相同完整层数及盒数，没有尾托、散盒或不满层。
- 空托盘默认高 160 mm、重 30 kg。每个装货托盘的地板重量 + 空托盘重量分别不超过单托限重，默认 1500 kg；上下托不合并校验单托限重。
- 预估整柜辅材重量默认 500 kg，可修改，仅计入整柜总重并占用货载额度，不分摊至单托。
- 20GP、40GP、40HQ、45HQ 初始使用修改逻辑表中的尺寸，货载默认均为 27000 kg。每种柜型分别记住最后输入的有效长宽高，切换柜型及重新打开时恢复；空值、非正数不覆盖已有记录。浏览器禁止本地存储时，尺寸只在当前页面会话内保留。
- 一盒限重、托盘限重和货柜限重分别保存最后输入的有效正数，刷新或重新打开后恢复。货柜限重跨柜型沿用，不因切换柜型重置；空值、非正数不覆盖已保存值。首次使用仍默认 25、1500、27000 kg。浏览器禁止本地存储时不能跨刷新保存。
- 需要人工提供的地板长、地板宽、主体厚度、底垫厚度、主体密度和每盒片数使用浅黄色背景标识；每盒片数位于单片地板参数区。
- 纸箱高度会按本体厚度、底垫厚度、每盒片数和高度余量自动填入，也可手动覆盖；点击“重置为默认”恢复自动联动。
- 常用托盘尺寸来自 `客户包装托盘汇总.xlsx`。先按地板长、宽、主体厚、底垫厚和每盒片数完整匹配；没有完整匹配时按地板长宽选择历史记录中最常见的托盘尺寸。没有长宽记录时保留当前托盘尺寸。
- 不另设安全高度或间隙。需要预留装卸空间时，直接扣减货柜内部可用尺寸。
- 可选择长沿柜长、长沿柜宽、允许横竖混排／错位、自动比较。上托与下托使用相同位置和方向，完整支撑，不跨托；最多两托高。上层可以只占部分底层位置，但每个装货托盘的盒数和层数完全相同。
- 单盒、单托、整柜限重和尺寸都必须满足。无可行方案时显示原因并清空旧方案和模型；不以超重结果充当有效装载方案。

### 装载搜索

二维摆放比较同向网格、沿两个轴的横竖分区，以及多种空余矩形填充策略，支持混排与错位。每层使用搜索所得最多盒数的完整布局。给定这一层内布局及搜索所得柜底摆法，枚举可装托盘数和一／两层叠托，求每托统一层数，使总 SQM 最大；面积相同优先少用托盘。复杂二维排布采用启发式搜索，不承诺数学上的全局最优。

页面不再显示装载建议，也不运行候选片数建议搜索。托盘摆放区域仅保留标题和选择框，计算规则不变。

同一摆放模块中提供独立的纸箱摆放选择：默认自动比较，也可限定纸箱长沿托盘长、纸箱长沿托盘宽、允许同层横竖混排，或使用交叉摆放。交叉摆放的奇数层统一沿托盘长，偶数层旋转 90°，各层盒数可不同，计算和 3D 均按实际奇偶层展示。

计算方式提供“单规格托盘”和“多尺寸托盘拼柜”。

多尺寸模式直接输入装货后的托盘外廓长、宽、高（含底座）及总重（含全部货物、纸箱和底座）。在托盘参数模块点击“将当前托盘加入下方清单”，再设置各类托盘的计划数量。四项数据完全相同的托盘合并计数，高度或重量不同的托盘分别保留。

多尺寸模式隐藏单片地板、包装、纸箱摆法、单盒及单托限重、预估辅材重量。限制条件仅使用货柜货载限重和内部可用尺寸；托盘在柜内的摆放方式独立保留。单规格和多尺寸托盘输入互不覆盖，切换模式保留会话内清单。整柜重量直接累计实装托盘总重，不再另加原来的 500 kg 辅材。

多尺寸搜索比较 5 种托盘排序、2 种方向偏好和 3 种剩余空间填充策略（共 30 个候选方案），以实装托数最多为目标，托数相同时优先包络体积占比高的方案。多尺寸模式不计算或优化 SQM。同规格最多叠两托，按输入的装货后总高检查叠放高度。需要现场条件允许叠放；算法不计算纸箱承压能力。结果列出各类计划／实装托数、装货尺寸、单托总重、整柜重量和包络体积占比，3D 显示实际装货托盘外廓。不再根据托盘外形推算地板面积、盒数或片数，且不保证复杂二维排布的全局最优。

多尺寸计算回归检查：运行 `node tests/loaded-pallet.test.cjs`。先前生成的验证工作簿记录的是 v6.0 地板规格推导模式，其“多尺寸拼柜”工作表不适用于当前直接输入模式。

计算使用未四舍五入的重量和尺寸；只在展示时取小数。3D 和汇总使用同一份实际排布数据。体积占比按含底座的托盘包络体积计算，不代表地板材料净体积。
